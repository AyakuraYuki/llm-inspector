evaluation 使用教程（Windows 电脑，写给不会写程序的人看）
================================================

这份教程教你怎么在自己的 Windows 电脑上，用这个小工具给某个 AI 大模型的接口做一次"全身体检"，
看看它是不是真的能正常、稳定、合规地对外提供服务。

这个小工具是干什么的？
----------------------

如果说 benchmark 是"考模型答题准不准"，那 evaluation 就是"体检模型这个服务本身靠不靠谱"。
它会从六个方面逐层检查：

1. 接口通不通、能不能正常对话
2. 各种协议细节是否支持（比如流式输出、多轮对话、返回 JSON 格式等）
3. 模型基本能力过不过关（内置一批中英文冒烟题）
4. 服务稳不稳定（同样的问题问几次答案是否一致、跑一段时间会不会出错变多）
5. 响应速度和吞吐能力
6. 遇到"不合法"的请求（比如故意传错参数）时，服务能不能正确拒绝

检查完之后，会给出一个总的结论：「通过」「有风险提示但可用」或者「不通过」，方便你直接判断
这个服务能不能放心接入。

你不需要看懂代码，只需要跟着下面的步骤做就行。

开始之前，你需要有这两样东西
----------------------------

打开工具所在的文件夹，你应该能看到这两个文件（名字可能略有不同，但差不多是这个意思）：

1. 「evaluation.exe」—— 这个就是工具本身
2. 「config.yml」—— 这是一张"填空表格"，你要在里面填上你的信息

如果这两个文件不在同一个文件夹里，先把它们放到一起。

另外，你还需要提前准备好两条信息（一般是给你提供 AI 服务的人或者公司给你的）：

- 一个网址，专业说法叫"接口地址"，样子大概是「http://localhost:8000/v1」或者
  「https://api.openai.com/v1」这样
- 一串密码，专业说法叫"令牌"，样子大概是「sk-xxxxxxxxxxxxxxxx」这样
- 还需要知道要测的模型叫什么名字，比如「qwen2.5-72b-instruct」

没有这些信息，工具是跑不起来的，先去问要这些信息的人拿到手。

第一步：填写"表格"
------------------

1. 用鼠标右键点一下「config.yml」这个文件
2. 选择"打开方式"，再选择"记事本"
3. 打开后你会看到一堆文字，最上面几行是这样的（前面带 # 的是说明文字，不用管它，也不用删）：

    target:
      base_url: http://localhost:8000/v1
      api_key: sk-xxx
      model: qwen2.5-72b-instruct
      protocol: openai

4. 把 base_url 后面的内容，换成别人给你的那个"接口地址"
5. 把 api_key 后面的内容，换成别人给你的那串"令牌"
6. 把 model 后面的内容，换成要测试的那个模型的名字
7. protocol 这一行，一般保持 openai 不动即可；只有对方明确告诉你这是 Anthropic（Claude）
   或者 Gemini 接口时，才需要改成 anthropic 或 gemini
8. 下面 layers 那一大段，保持默认（全部 enabled: true）就好，不用去动
9. 改完之后，按键盘上的 Ctrl + S 保存，然后直接关掉记事本窗口

小提醒：改的时候只改冒号 : 后面的内容，冒号本身和前面的字不要删，也不要多加空格、多加符号；
这份表格用缩进（前面的空格数量）来分层次，改内容时不要动前面的空格数量。

第二步：运行工具
----------------

Windows 电脑上，双击一个程序，窗口很可能一闪就没了，你根本看不清它说了什么。所以我们用一个
更靠谱的方法：

1. 打开 evaluation.exe 所在的那个文件夹
2. 在窗口最上面的"地址栏"（就是显示文件夹路径的那一条）上点一下，把里面的内容全部清空
3. 输入 cmd，然后按键盘上的 Enter（回车）键
4. 这时候会弹出一个黑底白字的窗口，这是正常的，不用害怕，这叫"命令提示符"
5. 在这个黑色窗口里输入 evaluation.exe run --config config.yml，再按一下 Enter
6. 工具就开始运行了

注意：这里是两个短横线「--config」，不是一个短横线，跟别的工具不太一样，输入的时候要看清楚。
「run」和「--config config.yml」这两段都不能省略。

如果你不小心把窗口关掉了，重新按上面 1~5 步再来一次就行。

第三步：等待，然后看结果
------------------------

工具跑起来之后，黑色窗口里会一层一层地打印检查过程，从第一层到第六层。整个过程通常几分钟到
十几分钟不等（性能测试那一层耗时会长一些），请耐心等它自己跑完，不要中途关闭窗口。

跑完之后，黑色窗口里会打印一份汇总报告，重点看下面这几处：

- 最上面一句话摘要，会直接告诉你整体是「通过」还是「有问题」
- 一张"体检结论表"，分别针对"接入与合规""性能画像""可用性冒烟"三个方面各给一个结论：
  「pass」（通过）、「warn」（有提示但不算硬伤）、「fail」（不通过）
- 只要"接入与合规"这一项是 fail，就说明这个服务存在比较严重的问题，不建议直接接入使用
- 如果只是"性能画像"或"可用性冒烟"是 warn，说明服务能用，但速度或稳定性上有一些瑕疵，可以
  酌情使用

同一个文件夹里会多出一个「reports」文件夹，里面按运行时间生成子文件夹，包含：

- 一份「report.json」，是给懂技术的同事看的详细数据
- 一份「report.md」，是排版好的完整报告，可以用记事本或者浏览器直接打开阅读

如果想让懂技术的同事进一步分析，把这个 reports 里对应的子文件夹发给他们就行。

常见问题
--------

【黑色窗口一闪就消失了，什么都没看到】
说明你是直接双击了 evaluation.exe，请按"第二步"里说的方法，通过 cmd 命令窗口来运行。

【忘了打两个短横线，只打了一个】
「--config」必须是两个短横线连在一起，只打一个短横线会导致工具报错或者报"未知选项"，回去
重新检查命令。

【提示跟 config 相关的报错，比如缺少必填字段】
说明"第一步"里 base_url / api_key / model 这三项没有填全，或者缩进被改动过，检查一下
内容和空格。

【第一层就直接失败并中止】
说明接口本身连不上或者鉴权失败，先确认 base_url、api_key 有没有抄错，网络是否正常。

【跑到一半卡住不动，或者提示超时】
可能是网络不好，或者对方服务器响应比较慢，多等一等；如果一直没反应，可以按 Ctrl + C
停下来，重新跑一次。

【出现一堆看不懂的英文错误】
不用一个字一个字看懂，把黑色窗口里的文字截图，或者把生成的 report.md 发给懂技术的同事看
就行。

【这次测试会不会花钱？】
会的。因为要真的向模型发送很多次请求，是会产生真实费用的，这是正常现象，不是工具出错。
