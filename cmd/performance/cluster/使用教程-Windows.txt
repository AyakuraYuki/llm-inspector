performance-cluster 使用教程（Windows 电脑，写给不会写程序的人看）
========================================================

这份教程教你怎么用这个小工具，同时调动几台电脑一起给某个 AI 大模型的接口做压力测试。它是
performance 工具的"多机版"，适合单独一台电脑测不出来的超大并发场景（比如同时模拟几千个人
一起用）。

这个小工具是干什么的？
----------------------

普通的 performance 工具只能靠一台电脑发请求，电脑本身的性能和网络会限制能模拟出多少"同时
使用的人数"。performance-cluster 则是找来好几台电脑一起干活：

- 找一台电脑当"指挥官"（专业说法叫 coordinator），负责读配置、分配任务、汇总结果、出报告
- 找几台电脑当"打工的"（专业说法叫 agent），负责真正去请求模型接口
- 指挥官会把"总共要模拟多少人"平均分给每一台打工的电脑，比如总共要 5000 人、分给 4 台电脑，
  每台电脑负责 1250 人
- 打工的电脑测完之后把原始数据交给指挥官，指挥官统一汇总、算出跟单机版一样口径的结果，
  再生成同样的 Excel 报表

这个工具比前面几个工具更复杂一些，因为它需要好几台电脑、需要它们互相能连通网络。如果你对
"IP 地址""内网""端口"这些词不熟悉，建议先找懂技术的同事一起完成，或者请他们帮忙准备好每台
电脑之后，你再照着本教程操作。

开始之前，你需要准备这些东西
----------------------------

1. 几台电脑：一台当"指挥官"（可以就是你自己现在用的这台 Windows 电脑），其余几台当
   "打工的"，它们必须在同一个内网里，互相能访问到对方（这一步最好请懂技术的同事帮忙确认）
2. 每台"打工的"电脑上要有跟它系统匹配的「performance-cluster」程序文件
3. 你这台"指挥官"电脑上要有「performance-cluster.exe」，以及一份「config.yaml」
   "填空表格"
4. 每台"打工的"电脑的 IP 地址（一串数字，比如 10.0.0.1），这个要问负责网络的同事拿到
5. 要测试的模型名称、接口地址、令牌（密钥），跟别的工具一样，一般由提供 AI 服务的人或者
   公司给你

安全提醒：这些电脑之间传输令牌等信息时是不加密的明文，所以必须确保它们都在你们自己可信的
内网环境里，不要跨公网使用这个功能。

第一步：在每台"打工的"电脑上启动 agent
--------------------------------------

这一步需要在每台"打工的"电脑上分别操作一次（如果这些电脑是 Linux 服务器，通常由懂技术的
同事远程操作完成，你只需要拿到它们的 IP 地址即可，可以跳过这一步直接看第二步）。

如果确实需要你自己动手，在那台电脑上打开对应系统的命令行窗口，进入放着 performance-cluster
程序的文件夹，输入：

    performance-cluster.exe agent -listen :7070

按 Enter 之后，这台电脑就会一直守着，等着"指挥官"给它派活，界面上不会有太多动静，这是正常
现象，不要关闭这个窗口。

第二步：在"指挥官"电脑（也就是你的 Windows 电脑）上填写"表格"
--------------------------------------------------------------

1. 用鼠标右键点一下「config.yaml」这个文件
2. 选择"打开方式"，再选择"记事本"
3. 打开后你会看到一堆文字，最上面是这样的一段（前面带 # 的是说明文字，不用管它，也不用删）：

    cluster:
      agents:
        - "10.0.0.1:7070"
        - "10.0.0.2:7070"
        - "10.0.0.3:7070"
      auth_token: ""
      poll_interval: 1s
      agent_timeout: 10s

4. 把 agents 下面的每一行，换成第一步里那几台"打工的"电脑的 IP 地址，后面的 :7070 保持不动
   （除非同事告知用了别的端口号），有几台电脑就写几行，多退少补
5. auth_token 一般留空即可，除非同事要求配置了共享密码，那就跟 agent 那边设置的一致
6. 往下找到 base_url，把双引号里的内容换成别人给你的那个"接口地址"
7. 往下找到 concurrency，这里的数字表示"全部电脑加起来总共模拟多少人"，比如：

    concurrency: [1000, 2000, 3000, 4000, 5000]

   如果不确定要不要改，保持默认或者按懂技术的同事的要求改
8. 往下找到 models 这一段，把 name 换成要测试的模型名字；再找到 token_groups 这一段，把
   双引号里的内容换成对应模型真正的令牌，做法跟单机版 performance 工具完全一样
9. 改完之后，按键盘上的 Ctrl + S 保存，然后直接关掉记事本窗口

小提醒：这份表格里，同一层级的内容前面空格数量必须一致，改内容时只改文字部分，不要动前面的
空格和短横线 - 。

第三步：在"指挥官"电脑上运行工具
--------------------------------

1. 打开 performance-cluster.exe 所在的那个文件夹
2. 在窗口最上面的"地址栏"（就是显示文件夹路径的那一条）上点一下，把里面的内容全部清空
3. 输入 cmd，然后按键盘上的 Enter（回车）键
4. 这时候会弹出一个黑底白字的窗口，这是正常的，不用害怕，这叫"命令提示符"
5. 在这个黑色窗口里输入 performance-cluster.exe run -config config.yaml，再按一下 Enter
6. 工具就开始运行了

注意：这里用的是子命令 run，而且只有一个短横线 -config，跟单机版 performance 工具（不用
写 -config）以及 evaluation 工具（两个短横线 --config）都不一样，输入时要看清楚。

如果你不小心把窗口关掉了，重新按上面 1~5 步再来一次就行。

第四步：等待，然后看结果
------------------------

工具会先逐台"打工的"电脑做连通性检查，任何一台连不上都会直接中止，并提示是哪一台出了问题。
都正常的话，就会开始按并发档位逐档测试，过程跟单机版 performance 基本一致：会出现自动刷新的
"仪表盘"界面，按 q 键或 Ctrl + C 可以随时结束当前测试并查看已完成部分的结果。

跑完之后，黑色窗口里会打印跟单机版一样格式的汇总表格，同一个文件夹里也会多出一个
「bench-cluster-一串数字.xlsx」的 Excel 文件，可以用 Excel 打开查看详细数据。

如果某台"打工的"电脑在测试过程中失联（比如网络断开、程序意外退出），整轮测试会直接以错误
结束（已经跑完的档位仍会正常出报告），并在每台电脑各自的文件夹里留有一份错误日志文件，名字
类似「bench-agent-一串字符-request-errors.jsonl」，需要的时候可以发给懂技术的同事查看。

常见问题
--------

【黑色窗口一闪就消失了，什么都没看到】
说明你是直接双击了 performance-cluster.exe，请按"第三步"里说的方法，通过 cmd 命令窗口
来运行，并且要带上 run -config config.yaml。

【提示某台 agent 连不上 / 探活失败】
先确认那台电脑上的 agent 有没有按第一步启动、IP 地址和端口有没有填对，以及两台电脑之间
网络是否互通（可以请负责网络的同事帮忙确认）。

【提示"配置缺少 cluster 段"】
说明 config.yaml 里没有正确填写第二步里的 cluster.agents 这部分内容，回去检查一下有没有
漏填或者缩进被改动过。

【提示 token_group 找不到令牌】
跟单机版一样，是 models 里填的 token_group 名字，和下面 token_groups 里的分组名字没有对上，
两边要完全一致。

【测试中途某台电脑掉线，整轮测试直接失败了】
这是设计好的行为：既然承诺了总共模拟多少人，只要少了一台电脑，剩下的数据就不能代表原本的
测试目标，所以工具选择直接报错，而不是悄悄少测一部分却不告诉你。重新确认好网络之后再跑一次
即可。

【这次测试会不会花钱？】
会的。因为要真的向模型发送大量请求，是会产生真实费用的，多台电脑同时压测意味着请求量更大，
费用可能比单机版更高，这是正常现象，不是工具出错。
