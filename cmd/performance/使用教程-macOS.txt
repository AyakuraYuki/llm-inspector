performance 使用教程（Mac 电脑，写给不会写程序的人看）
============================================

这份教程教你怎么在自己的 Mac 电脑上，用这个小工具去压测一下某个 AI 大模型的接口，看看它在
很多人同时使用的时候，速度还能不能扛得住。

这个小工具是干什么的？
----------------------

你可以把 AI 大模型的接口想象成一个"餐厅的后厨"。这个工具会模拟很多个"顾客"同时点餐（同时
向模型发请求），然后测出：

- 顾客等第一口菜（第一个字）要多久
- 后厨整体一分钟能出多少菜（每秒能处理多少文字）
- 同时来 10 个顾客、50 个顾客、100 个顾客……分别会怎样，扛不扛得住
- 有没有顾客的单子直接失败（请求出错）

它会自动生成一份 Excel 表格，把这些数据整理得清清楚楚，方便直接拿去汇报或者对比。

你不需要看懂代码，只需要跟着下面的步骤做就行。

开始之前，你需要有这两样东西
----------------------------

打开工具所在的文件夹，你应该能看到这两个文件（名字可能略有不同，但差不多是这个意思）：

1. 「performance」—— 这个就是工具本身（Mac 上的程序一般没有后缀名，不会写成 .exe）
2. 「config.yaml」—— 这是一张"填空表格"，你要在里面填上你的信息

如果这两个文件不在同一个文件夹里，先把它们放到一起。

另外，你还需要提前准备好这些信息（一般是给你提供 AI 服务的人或者公司给你的）：

- 一个接口地址，比如「https://api.openai.com」
- 要测试的一个或多个模型名称，比如「gpt-5.6-sol」
- 每个模型对应的令牌（密钥），样子大概是「sk-xxxxxxxxxxxxxxxx」这样

这个工具比前面几个稍微复杂一点，因为它一次可以测好几个模型、每个模型还可能对应不同的令牌，
如果你不确定该怎么填，最好先找懂技术的同事帮你确认一遍再动手。

第一步：填写"表格"
------------------

1. 用鼠标右键点一下「config.yaml」这个文件（触控板是用两个手指点一下）
2. 选择"打开方式"，再选择"文本编辑"（TextEdit，Mac 自带的软件）
3. 打开后你会看到一堆文字，重点看下面这几处（前面带 # 的是说明文字，不用管它，也不用删）：

    base_url: "https://api.openai.com"
    duration: 60s
    concurrency: [10, 20, 30, 40, 50, 75, 100, 120, 150]

4. 把 base_url 后面双引号里的内容，换成别人给你的那个"接口地址"
5. 「duration」是每一档测试跑多久，「concurrency」是要测试的"同时人数"档位列表，一般不用
   改，除非懂技术的同事让你调整
6. 往下找到 models 这一段，类似这样：

    models:
      - name: "gpt-5.6-sol"
        provider: "openai"
        token_group: "openai-channel"

   把 name 换成要测试的模型名字，provider 一般保持 openai 不动（除非对方明确说是 Anthropic
   或者 Gemini 接口），token_group 是给这个模型分配一个"令牌组"的名字，可以保持默认或者按
   同事的要求改
7. 再往下找到 token_groups 这一段，类似这样：

    token_groups:
      openai-channel:
        - "sk-openai-abcdef0123456789"

   把双引号里的内容换成对应模型真正的令牌，令牌组的名字（这里是 openai-channel）要跟上一步
   models 里填的 token_group 完全对得上
8. 如果只测一个模型，保持文件里默认的一组 models/token_groups 结构，把里面的名字和令牌换掉
   即可；不需要用到的模型条目可以直接删掉整个 - name: ... 块
9. 改完之后，按键盘上的 Command + S 保存。如果弹出一个小窗口问你要保存成什么格式，直接点
   "保留原有格式"或者带 .yaml 那个选项就行，千万别选成 .txt

小提醒：这份表格里，同一层级的内容前面空格数量必须一致，改内容时只改文字部分，不要动前面的
空格和短横线 - 。

第二步：运行工具
----------------

Mac 上运行这类工具，需要用到一个叫"终端"（Terminal）的自带软件，黑底白字（或者白底黑字），
看起来有点吓人，但只需要打几个字就行，跟着做就好。

1. 按键盘上的 Command + 空格键，屏幕中间会出现一个搜索框
2. 输入"终端"（或者英文 Terminal），看到图标后按一下 Enter（回车），"终端"窗口就打开了
3. 接下来要让终端"走到"工具所在的文件夹。最简单的办法：在终端窗口里先输入 cd
   （注意 cd 后面有一个空格，先不要按回车）
4. 然后用鼠标把装着 performance 和 config.yaml 的那个文件夹，直接从 Finder 窗口"拖"到
   终端窗口里，松开鼠标，终端会自动把这个文件夹的路径帮你打好
5. 这时候按一下 Enter（回车），终端就"走到"这个文件夹里了
6. 接着输入 chmod +x performance，按 Enter（这一步是给这个工具"盖章"，允许它被执行，
   只需要做一次）
7. 最后输入 ./performance，按 Enter，工具就开始运行了

因为 config.yaml 这个文件名是工具默认会去找的名字，所以不用像 benchmark 那样额外输入
-config，直接 ./performance 就行。

如果这时候屏幕上弹出一个提示，说"无法打开，因为无法验证开发者"或者类似的话，不用怕，这是
Mac 的安全保护机制，看下面"常见问题"里的解决办法。

第三步：等待，然后看结果
------------------------

工具跑起来之后，如果是在正常的终端窗口里运行，会出现一个会自动刷新的"仪表盘"界面（专业说法
叫 TUI），实时显示当前测试进度、速度等信息。如果不想看这个界面，也可以在测试过程中按一下
q 键或者 Ctrl + C，会立刻结束并输出目前已经跑完的结果。

整个测试会按"同时人数"档位一档一档往上测（比如先测 10 人同时用，再测 20 人……），每一档都
要跑满设定的时长，所以整个过程可能要跑十几分钟到几十分钟，请耐心等待，不要中途关闭终端窗口
（除非你确认要提前结束）。

跑完之后，终端里会打印一份汇总表格，类似这样：

    SUMMARY TABLE
    --------------------------------------------------------------------------
    Model (Provider)        Token Group       Conc   QPS       TPS       TTFT P50    TTFT P95    I/O Ratio
    --------------------------------------------------------------------------
    gpt-5.6-sol (openai)    openai-channel    50     13.500    2650.3    320.5ms     680.2ms     0.081

重点看这几列：

- 「QPS」：每秒能处理多少个请求，数字越高说明越能扛住并发
- 「TPS」：每秒能生成多少文字，数字越高说明模型吐字越快
- 「TTFT P50/P95」：大多数情况下（P50）和绝大多数情况下（P95）用户等第一个字要多久，数字
  越小越好
- 如果某一档旁边有 [WARN] 提示，说明这一档可能出了问题（比如失败率太高、被提前终止），可以
  截图发给懂技术的同事看

同一个文件夹里会多出一个「bench-一串数字.xlsx」的 Excel 文件，数字是运行的日期和时间，方便
区分是哪一次跑的结果。用 Numbers 或者 Excel 打开就能看到更详细的分析表格，可以直接拿去汇报
或者跟其他厂商的结果对比。

常见问题
--------

【提示"无法打开，因为无法验证开发者"或"来自身份不明的开发者"】
这是 Mac 自带的安全保护，遇到这个提示按下面任意一种方法处理：

- 方法一（推荐）：在 Finder 里找到 performance 这个文件，用鼠标右键点一下它（或者按住
  Control 键再点一下），选择"打开"，会弹出一个确认框，再点一次"打开"就行，以后就不会再
  提示了
- 方法二：打开"系统设置"（苹果菜单里能找到）→"隐私与安全性"，往下滑，能看到一条关于
  performance 被阻止的提示，点旁边的"仍要打开"，可能需要输入一下你的电脑密码

【终端里提示 "Permission denied"（权限不够）】
说明"第二步"里第 6 步的 chmod +x performance 没有执行成功，回去重新输入一次这条命令，再
运行。

【终端里提示 "No such file or directory"（找不到文件）】
说明终端现在所在的文件夹不对，回去重新做"第二步"里第 3~5 步，把文件夹重新拖进终端一次。

【一开始就直接报错退出，还没开始测】
工具会先对每个模型做一次连通性检测，只要有一个模型失败，整轮测试就会直接中止。检查一下
config.yaml 里对应模型的 token_group 和令牌是否填对，网络是否正常。

【提示 token_group 找不到令牌】
说明 models 里某个模型填的 token_group 名字，在下面的 token_groups 里没有对应的分组，
两边名字要完全一致（大小写、短横线都要一样）。

【终端窗口花花的，看不清楚在跑什么】
这是正常的仪表盘界面，按一下 q 键可以随时结束并查看当前结果；如果实在不想看这个界面，可以
让懂技术的同事帮忙在 config.yaml 里把 no_tui 改成 true。

【跑到一半卡住不动，或者提示超时】
可能是网络不好，或者对方服务器响应比较慢；如果一直没反应，可以按 q 键或 Ctrl + C 结束当前
这一档，工具会输出已经跑完部分的结果。

【这次测试会不会花钱？】
会的。因为要真的向模型发送大量请求，是会产生真实费用的，并发档位越高、跑的时间越长，费用
也会越高，这是正常现象，不是工具出错。
