benchmark 使用教程（Windows 电脑，写给不会写程序的人看）
================================================

这份教程教你怎么在自己的 Windows 电脑上，用这个小工具去考一考某个 AI 大模型，看看它答题
准不准、反应快不快。

这个小工具是干什么的？
----------------------

你可以把 AI 大模型想象成一个"参加考试的学生"。这个工具会拿一批现成的题目（比如高难度数学题、
各学科选择题）去问模型，然后：

- 自动对照标准答案，看模型答得对不对，算出一个"正确率"
- 记录模型答题的速度，比如第一个字多久出来、每秒能吐多少字
- 把每一题的完整过程都存成文件，方便回头查看

你不需要看懂代码，只需要跟着下面的步骤做就行。

开始之前，你需要有这两样东西
----------------------------

打开工具所在的文件夹，你应该能看到这两个文件（名字可能略有不同，但差不多是这个意思）：

1. 「benchmark.exe」—— 这个就是工具本身
2. 「config.yml」—— 这是一张"填空表格"，你要在里面填上你的信息

如果这两个文件不在同一个文件夹里，先把它们放到一起。

另外，你还需要提前准备好两条信息（一般是给你提供 AI 服务的人或者公司给你的）：

- 一个网址，专业说法叫"接口地址"，样子大概是「https://api.openai.com/v1」这样
- 一串密码，专业说法叫"密钥"，样子大概是「sk-xxxxxxxxxxxxxxxx」这样
- 还需要知道要测的模型叫什么名字，比如「gpt-4」

没有这些信息，工具是跑不起来的，先去问要这些信息的人拿到手。

第一步：填写"表格"
------------------

1. 用鼠标右键点一下「config.yml」这个文件
2. 选择"打开方式"，再选择"记事本"
3. 打开后你会看到一堆文字，最上面几行是这样的（前面带 # 的是说明文字，不用管它，也不用删）：

    base_url: "https://api.openai.com/v1"
    api_key: "sk-xxx"
    model: "gpt-4"
    max_tokens: 65536
    max_workers: 1

4. 把 base_url 后面双引号里的内容，换成别人给你的那个"网址"
5. 把 api_key 后面双引号里的内容，换成别人给你的那串"密钥"
6. 把 model 后面双引号里的内容，换成要测试的那个模型的名字
7. 其他内容（max_tokens、max_workers、下面的 dataset 题库开关等）保持不动，工具已经
   内置了一批默认题目，不用你自己准备
8. 改完之后，按键盘上的 Ctrl + S 保存，然后直接关掉记事本窗口

小提醒：改的时候只改双引号里面的内容，双引号本身、冒号、前面的字都不要删，也不要多加空格、
多加符号。

第二步：运行工具
----------------

Windows 电脑上，双击一个程序，窗口很可能一闪就没了，你根本看不清它说了什么。所以我们用一个
更靠谱的方法：

1. 打开 benchmark.exe 所在的那个文件夹
2. 在窗口最上面的"地址栏"（就是显示文件夹路径的那一条）上点一下，把里面的内容全部清空
3. 输入 cmd，然后按键盘上的 Enter（回车）键
4. 这时候会弹出一个黑底白字的窗口，这是正常的，不用害怕，这叫"命令提示符"
5. 在这个黑色窗口里输入 benchmark.exe -config config.yml，再按一下 Enter
6. 工具就开始运行了

注意：「-config config.yml」这一段必须原样输入，不能省略，否则工具会直接报错退出，提示
"缺少 -config"。

如果你不小心把窗口关掉了，重新按上面 1~5 步再来一次就行。

第三步：等待，然后看结果
------------------------

工具跑起来之后，黑色窗口里会不断刷出一行一行的文字，类似这样：

    [14:30:25] Loaded 33 questions
    [14:30:25] Benchmark started
    [14:30:25] Question 1 started
    [14:30:26] Question 1 first token received (TTFT=250ms)
    [14:30:40] Question 1 completed (1/33 done): TTFT=250ms, Total=15000ms, Tokens=1500, TPS=100.00 ✓ Correct

这是它在一条一条地测试。每隔 30 秒还会打印一次整体进度。整个过程可能要跑几分钟到十几分钟
不等，具体看题目数量和模型速度，请耐心等它自己跑完，不要中途关闭窗口。

跑完之后，黑色窗口最下面会打印一份总结，大概是这样：

    ============================================================
    BENCHMARK STATISTICS
    ============================================================
    Total questions: 33
    Successful: 33
    Failed: 0
    Questions with answers: 32
    Correct answers: 28
    Wrong answers: 4
    Accuracy: 87.50%
    Average TTFT: 245 ms
    Average TPS: 98.50
    ============================================================

重点看这几个数字：

- 「Accuracy」（正确率）：模型答对了百分之多少，数字越高说明这个模型答题越靠谱
- 「Failed」：有几道题请求失败了（网络问题、超时等），正常情况下应该是 0 或很小
- 「Average TTFT」「Average TPS」：反映模型反应快不快、吐字快不快

同一个文件夹里还会多出一个「reports_一串数字」的文件夹，数字是运行的日期和时间，方便区分
是哪一次跑的结果。里面有：

- 一个「benchmark_results.json」，记录了每道题的详细数据
- 每道题各有一份「question_编号_数据集名.txt」，里面是这道题的完整问答过程

如果想让懂技术的同事进一步分析，把这整个「reports_一串数字」文件夹发给他们就行。

常见问题
--------

【黑色窗口一闪就消失了，什么都没看到】
说明你是直接双击了 benchmark.exe，请按"第二步"里说的方法，通过 cmd 命令窗口来运行。

【提示"错误: 缺少 -config"】
说明运行的时候忘了带上「-config config.yml」这一段，回去重新输入完整的命令。

【提示"配置错误: 缺少 base_url / api_key / model"】
说明"第一步"里这三项没有填全，检查一下双引号里是不是都填上了内容。

【提示"配置错误: 缺少测试数据集"】
一般不会遇到，除非有人把 config.yml 里 dataset 下面的开关全改成了 false，又没有填
custom_questions。回去检查一下这部分内容是否被误改过。

【跑到一半卡住不动，或者提示超时】
可能是网络不好，或者对方服务器响应比较慢，多等一等；如果一直没反应，可以按 Ctrl + C
停下来，重新跑一次。

【题目跑得特别慢，好像要跑很久】
如果配置里开启了很大的题库（比如 MMLU-Pro 全集），题量会很大，跑完需要较长时间，这是正常
现象，不是工具卡死了。

【出现一堆看不懂的英文错误】
不用一个字一个字看懂，把黑色窗口里的文字截图，或者把生成的 reports 文件夹发给懂技术的同事
看就行。

【这次测试会不会花钱？】
会的。因为要真的让模型回答很多道题，是会产生真实费用的，这是正常现象，不是工具出错。
